# 微信中文事件播放序号兼容修复

## Intent

**Problem:** 用户确切指令为“播放第一条”，旧解析只接受阿拉伯数字，会把中文序号当作无法识别的摄像头选择器。另经隔离复现，“播放第1条事件”会重新查询今天全部摄像头，偏离本人刚查询的日期和摄像头列表。

**Approach:** 只扩展完整独立的“播放第…条/段”指令，支持规范中文序号及可选“事件/事件录像”后缀；统一从本人15分钟有效列表取片。中文序号解析不用于改写相机名称或日期，原显式查询路径、授权及文件校验保持原有规则。无列表、过期、非法、重复或越界序号不重新查询全部摄像头，不发送其他录像。

新增6项回归，并扩展第500条边界：最终完整测试194项全部通过，无跳过。独立Windows EXE通过6项启动、10项预览模拟及5项中文事件模拟检查，实际执行“今天事件→播放第一条”，合成录像上传加密还原后与原始字节一致；不代表真实手机收件。

独立盲审未发现新增可行动问题。修复版 EXE 已替换当前本机候选，SHA-256为 `8ec191a8a87d2a635a33811ff3c8ec4121ea335a827d1bb302f5d9d8c1dbf36b`，135,527,577字节；保留微信登录和录像目录，未启动远程中继、未更新旧安装程序或GitHub。真实微信验证结果见验证记录，不借用前一EXE的手机或镜头验收。

2026-10-19，用户在该修复版中依次发送“今天事件”“播放第一条”，明确确认“收到视频，而且能播放”。当前账号、电脑、手机下的真实收件和播放通过，其他环境和长期稳定性未验收。
