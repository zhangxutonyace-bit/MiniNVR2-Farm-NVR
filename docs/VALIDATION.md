## 人物框连续跟随：本机开发候选（2026-10-19）

实现约束见 [冻结规格](implementation/spec-stable-person-event-boxes.md)。自动/Haar 模式的标注采用独立 NanoDet `person` 定位和前后向 LK 图像跟踪，不使用 Hub 的轮廓作为人物种子；移动模式保留移动区域语义。检测位移完整应用，仅平滑局部残差与尺寸。漏检期间必须有当前帧图像支持，且人物确认在 0.75 秒内；光流不能刷新确认时间。来源、原图尺寸、乱序、过长帧间隔和空输入会重置。模型或处理失败保留原帧，沿用每摄像头一个在途作业和 0.5 秒等待预算。

新增 `tests/test_target_tracking.py` 提供带标签的 480×270/8fps 纹理目标与 MP4 编解码测试，覆盖运动、漏两次确认、中心与尺寸抖动、离开、快跳、背景错误支撑、双目标、静止、重置和原图不变；其标签只证明合成目标的跟踪行为，不能证明真人精度。`tests/test_event_overlay.py` 另覆盖语义定位与事件元数据隔离、真实编码、超时以及跨事件作业隔离。输出 MP4 解码测试实际经过 auto/Haar 标注、8/20 像素每帧移动和两帧漏检，从新增颜色像素提框；至少95%受支持帧的中心误差不超过6像素，静止标签的抖动减少至少25%，确认失效后不超过0.75秒清框。像素中心按描边的离散端点计算，未放宽规格容差。

## 历史：事件录像目标框本机 Windows 测试版（2026-10-19）

已按批准的 [实现规格](implementation/spec-event-target-boxes.md) 开发：新事件默认将目标框写入 MP4 像素，缺少新增字段的旧配置也默认打开。提供 FigJam 指定的红、橙、深蓝三色描边；开关和颜色在事件开始时固定。开启时两种来源都使用共享预览 JPEG 编码为 H.264，RTSP 分辨率可能降为通常宽 480 像素，CPU 占用增加。关闭保留既有 RTSP 原流路径和电脑摄像头单次设备采集。

检测布尔规则、阈值、确认次数、冷却及离开计时保持原逻辑。编码器持有独立 MOG2 与 Haar 实例；Haar 框使用候选区域内真实确认位置加偏移，自动模式只画匹配启发式的候选，移动模式画移动区域。JPEG、序号、来源和触发元数据成对传递，不把旧坐标画到新帧；预热、阴性、离线、过期及来源/尺寸变化会清除对应标注状态。预览与抽帧沿用原 JPEG。

源码离线用例覆盖三种颜色、两种来源、启停开关、帧对应、ROI 偏移、模型隔离、设置原子拒绝、事件内固定设置、写入阻塞与失败、实际 MP4 解码彩色像素，以及“今天事件 → 播放第一条”的模拟 CDN 加密上传/解密逐字节一致。共享编码录像先写 `.part.mp4`，只有编码正常结束、首帧可解码且尾部2秒区域完整解码到文件结束才原子发布，校验限时3秒；短片不足2秒时从开头校验至结束。这不是长录像中间部分的逐帧审计。编码正常但校验失败或超时，会保留原字节为待校验 `.part.mp4` 并显示提示，供后续人工恢复；文件仍对回放、下载和微信隐藏。编码失败或空文件可以删除。

每路摄像头最多一个在执行或待返回的画框任务。编码线程最多等待0.5秒，超时后该事件改用原画面并提示；旧任务未返回期间，同路后续事件继续使用原画面，不堆积任务。Python不能安全中止阻塞的原生OpenCV调用，因此保留该唯一退役任务，返回后丢弃结果，新事件可使用新的独立检测器；停止录像无需等待此原生任务。事件代次与警告状态使用短锁保护，旧回调不能覆盖新事件提示。异常类型和原因仅写入日志，原因去除网址凭据、换行并限长160字符；界面保持通用提示，日志写入失败也继续保留原画面。

审查修补另覆盖：确定性阻塞任务跨多事件的数量上限、及时停止和可播放原画面、释放后的新任务恢复与旧坐标/旧提示隔离、新序号MP4中框移动及阴性帧清框、第一事件保持红色而下一启用事件变蓝、禁用路径、末尾截断的真实MP4拒绝，以及 `null`、`false`、`0`、`[]` 顶层设置整单拒绝且配置字节不变。最后增加三项取消窗口检查：调用前已取消、槽位竞争期间取消、线程启动期间取消；这些情况下不启动新的原生检测调用。
