# MiniNVR2 Windows 下载版先读说明

本地候选版本：3.0.0。目标系统：Windows 10 / Windows 11，64 位（x64）。V3 尚未发布，文中公开下载链接仍指向 v2.4.0；不要将其当成 V3 下载。

V3 包内另附“算法商城-操作步骤.txt”。进入算法商城，选择内置模型或下载一个 YOLOX 模型，再勾选目标并点击应用；下载本身不启用算法。详见 [算法商城操作步骤](ALGORITHM_STORE_QUICK_START.md)。V3 的“人形检测”改称“事件检测”，“识别人”改称“参与检测”；原有微信与预览步骤保持可用。

V3 商城的新事件录像按类别固定四色描边，并附中文类别标签，色样可在商城勾选项前查看；颜色不代表危险等级、身份或跟踪编号。中文字体随包离线附带。原始预览、抽帧及旧录像不改变；旧检测模式仍使用全局三色。

这是已经打包的桌面程序，包含 Python 运行环境、网页资源、OpenCV 检测模型和 FFmpeg，无需另外安装 Python。

解压后附有五份说明：`先读我-使用说明.txt`、`电脑内置USB摄像头-操作步骤.txt`、`微信ClawBot-操作步骤.txt`、`微信局域网预览-操作步骤.txt`、`微信远程预览-操作步骤.txt`。用记事本打开即可查看摄像头接入、扫码、录像查询和预览配置。

## 第一次使用

1. 下载 [MiniNVR2-v2.4.0-windows-x64.zip](https://github.com/zhangxutonyace-bit/MiniNVR2-Farm-NVR/releases/download/v2.4.0/MiniNVR2-v2.4.0-windows-x64.zip)。
2. 将整个压缩包完整解压到你有写入权限的文件夹。保留包内的说明和第三方许可文件，不要在压缩软件中直接运行，也不要放在需要管理员权限才能写入的程序目录。
3. 双击解压后的 `MiniNVR2.exe`。程序会在后台运行，并打开默认浏览器。如果浏览器没有自动打开，可以在这台电脑上手动访问 `http://localhost:8800`。
4. 首次启动没有摄像头。打开“摄像头”页面，手动添加自己有权使用的 RTSP 摄像头，或在“电脑摄像头”点击“刷新设备列表”，选择内置 / USB 摄像头并“添加并启用”。选择本机设备后才开始采集，不采集麦克风。RTSP 地址以设备说明书为准，账号只在本机填写。
5. 在“预览”中确认画面在线，再按现场光线、距离和画面变化调整检测设置。在“回放”中查看已完成的事件录像及按日合成的抽帧录像。当日抽帧通常到次日才合成。
6. 退出时，右键系统托盘中的 MiniNVR2 图标并选择“退出”，或使用网页“设置”中的“退出程序”。关闭浏览器标签页不会停止录像。

请先用一台摄像头验证，再逐步增加路数。可接路数、预览流畅度与录像效果取决于笔记本性能、设备编码、分辨率和网络状态。笔记本休眠、关机或程序退出后，无法继续录像；需要持续录像时，请在 Windows 设置中自行安排电源和休眠策略。

## 数据保存与访问

程序首次运行后会在 EXE 所在文件夹创建 `data` 目录，保存配置、日志和录像。若该目录不可写，程序会尝试用户目录下的 `NVRData`。下载包本身不附带配置、日志、真实录像、设备账号或邮箱凭据。

本机配置可能保存摄像头密码、邮箱授权码或微信会话资料，请按个人资料保管；不要把运行后生成的 `data` 或 `NVRData` 整包公开上传。更新版本前先正常退出并备份自己的数据；建议将新版解压到新文件夹，再按需要迁移数据。

管理页面默认只允许本机访问。如果浏览器提示无法连接，先确认程序仍在运行，且没有另一个 MiniNVR2 实例占用 8800 端口。程序不会自动扫描局域网，先使用手工添加摄像头的方式。

这是本地桌面工具。若需要从局域网访问完整管理页面，需先设置访问口令，再按仓库说明启动。下方的微信预览使用独立入口，只提供指定摄像头的当前画面，不会开放完整管理页面或整个局域网。

## 微信 ClawBot 与邮件

启用并完成微信 ClawBot 接入后，可以通过微信查询指定摄像头、指定日期的事件列表，选择已结束的事件录像回传，也可以查询抽帧录像。这可以让笔记本在家里运行，人在外面通过熟悉的微信入口回顾画面。

在网页“设置”中启用微信并保存，点击“扫码登录”，用手机微信扫描并确认。保持程序运行和联网，然后在机器人聊天里每次单独发送一个指令。

微信事件指令：`今天事件`、`昨天事件 农场`、`事件 2026-10-18 1号` 查看列表；`最新事件` 直接取今天最近一段。列表每页10条，回复 `播放第2条`、`下一页`、`上一页` 选择和翻页，15分钟内有效且仅本人可用。v2.4.0 已修复中文序号，可先发 `今天事件`，收到列表后再单独发 `播放第一条`，也兼容 `播放第1条`；每次只发一个指令。只提供已结束的录像，超过配置的视频大小上限会提示而不上传。

查看已保存的事件录像无需安装 NetBird，也无需开启局域网或远程预览。2026-10-19，用户曾在 v2.4.0 最终修复程序的新事件中确认“框能跟随，电脑和微信播放正常”。该历史结果只覆盖当次电脑、摄像头、扫码账号和测试过程，不代表 V3 的人物跟随、多目标检测或微信实机验收；V3 需分别测试新事件。邮件及微信默认关闭；需要时请由本人完成账号配置。

## 电脑摄像头与事件人物框

在“摄像头 → 电脑摄像头”刷新并选择内置 / USB 设备，添加后到“预览”确认画面。若无画面，先关闭占用镜头的相机或视频会议软件，再检查 Windows 对桌面应用的摄像头访问权限。停用、删除或退出程序会释放镜头；程序不自动修改权限或安装驱动。

需要事件录像时，在“设置 → 事件检测”打开“启用检测”（旧版称“人形检测”），并确认该路摄像头的“参与检测”开关打开（旧版称“识别人”）。旧模式保持原触发算法；在商城应用模型后，选中目标的语义检测结果按原有连续命中、离开延时等参数触发和结束录像。让选中目标进入画面，再离开、等待片段结束，然后到“回放”选择“事件录像”；静止的选中物品也可能持续触发录像。

“设置 → 录像 → 事件录像显示目标框”默认打开，颜色可选红、橙、深蓝；颜色只便于看清，不代表危险等级。保存设置后从下一次事件生效。自动 / Haar 模式使用包内离线 NanoDet 人物模型加连续跟踪画框，移动模式只画移动区域。新 MP4 自带框，电脑回放和微信收到的是同一个已完成文件，旧录像不会补框。

在自动 / Haar 等旧检测模式下，内置人物画框模型仅负责定位，不改变原有事件触发算法，无需联网下载；商城模式则使用所选模型的目标类别结果触发事件，并标注相同类别，YOLOX 需先手动下载。遮挡、远处小人或快速转身仍可能漏框，模型或处理超时会保留原画面并提示。开启画框需要重新编码，可能增加 CPU 占用，RTSP 录像清晰度可能降到共享预览大小（通常宽480像素）；关闭画框恢复原录像方式。编码正常但首尾校验失败或超时的片段会保留为待校验文件，暂不提供回放或微信取回。

## 微信在外网查看当前画面

手机可使用移动网络或其他 Wi-Fi，**不用安装 NetBird 或额外 VPN 应用**。电脑和摄像头仍连接原来的局域网；只有电脑需要安装 NetBird。

1. 在电脑“预览”页确认摄像头画面正常。启用微信并扫码，确认“已登录，正在接收微信消息”。不需要先录制事件。
2. 从 [NetBird 官网](https://netbird.io/download) 在电脑安装 Windows 客户端，由你注册或登录自己的 NetBird 账号，确认显示 **Connected**。安装会添加网络组件和后台服务。
3. 用同一个 NetBird 账号登录[网页控制台](https://app.netbird.io/)。在 **Access Control → Groups** 建立仅包含本机的组；在 **Settings → Clients → Peer Expose** 开启 **Enable Peer Expose**，仅允许该组并保存。
4. 在 MiniNVR2“设置 → 微信远程预览”勾选 **“微信优先使用远程预览链接”**，点击 **“保存设置”**。
5. 阅读转发说明，点击 **“同意转发并开启远程预览”**，等待连接就绪。
6. 手机关闭 Wi-Fi、使用移动数据，在微信单独发送 **`预览1号`** 或 **`预览 摄像头名称`**，点击回复中的 **“打开实时预览”**，确认画面持续更新。

电脑需保持开机、联网且不休眠，MiniNVR2 持续运行。每次程序重启后，都要在电脑手动重新开启远程预览。单路链接10分钟有效，请勿转发；过期后重新发指令，点击最新回复。画面约每秒刷新一次，无声音。不使用时点击“停止远程预览”。

画面会经 NetBird 云端 HTTPS 代理转发，**服务商能够处理转发的画面**；确认接受后再开启。免费档、测试阶段功能和使用限制由服务商决定，不承诺永久免费或所有网络都可达。完整步骤和排查见包内 `微信远程预览-操作步骤.txt`。

## 微信查看同一 Wi-Fi 的当前画面

无需先录制事件。手机和运行 MiniNVR2 的电脑应连接同一个可信 Wi-Fi，电脑保持开机，程序持续运行。

1. 在电脑“预览”页确认摄像头已有正常画面。
2. 在“设置 → 微信 ClawBot”启用微信并保存，点击“扫码登录”，用自己的手机微信扫码确认。状态应显示“已登录，正在接收微信消息”；已登录时无需重复扫码。
3. 先取消“微信优先使用远程预览链接”；再在“微信局域网预览（同一 Wi-Fi）”勾选“启用局域网预览”。“本机 Wi-Fi IPv4”先留空自动选择，端口保留 `8803`，点击“保存设置”，确认预览状态为“已开启”。
4. 在手机的微信 ClawBot 聊天中，单独发送 `预览1号`；也可以发送 `预览 摄像头名称`，将“摄像头名称”换成自己的设备名称。
5. 点击返回的链接查看当前画面。页面约每秒刷新一次，无声音；每条链接只对应一台摄像头，有效期10分钟，请勿转发。

链接到期、程序重启或更新后，重新发预览指令取得新链接。关闭局域网预览或退出微信登录也会使旧链接失效。此链接不能进入管理页面，也不能下载录像。

打不开时，先确认手机仍使用同一个 Wi-Fi，没有切到移动数据；访客 Wi-Fi 的设备隔离可能阻止手机连接电脑。若自动地址不对，在 Windows“设置 → 网络和 Internet → Wi-Fi → 当前网络属性”找到这台电脑的 IPv4 地址，填入“本机 Wi-Fi IPv4”后保存，再请求新链接，不要填写手机或其他设备的地址。检查 Windows 防火墙是否允许 MiniNVR2 在专用网络接收连接；不要关闭整个防火墙，程序不会自动修改规则。机器人不回复时，检查微信登录及接消息状态、设置页错误提示；只有提示登录过期时才重新扫码。详细步骤见包内 `微信局域网预览-操作步骤.txt`。

同一 Wi-Fi 预览的历史手机验收使用 v2.2.3：2026-10-19，用户通过真实微信点击链接，确认画面持续更新，未修改防火墙。该结果仅覆盖当次电脑、账号、手机与网络，未独立核验设备型号或实际场景。

## 已有验证范围

v2.4.0 的47项跟踪定向测试、16项 Windows 发布分发检查通过。最终 EXE 通过6项启动、10项模拟预览、模型与许可资源核验，以及带框事件 MP4 和模拟微信加密回传逐字节一致检查。最终245项完整回归重跑有1项既有 Windows 临时文件占用准备错误（其余244项通过），该项单独复核通过；不能称完整套件全部通过。该问题与原有配置保存相关，记录见仓库 `docs/VALIDATION.md`。

2026-10-19，用户在 v2.4.0 最终修复版中实测新事件，确认人物框能跟随，电脑和微信视频均能播放。该结果不代表 V3 实机验收，V3 需重新验证。跨网段预览的历史验收来自 v2.3.0：用户用手机移动数据，在微信重新取链接并点击“打开实时预览”，确认合成画面持续更新，手机没有安装额外 VPN 应用。

上述事件和预览验收分别绑定对应版本的 EXE，不混用证据；仅覆盖当次电脑、扫码账号、手机与网络。外网预览旧链接曾显示失效，具体原因未知；重新取新链接后成功，未将其推断为代理或有效期问题。

v2.4.0 保留已有远程预览逻辑并通过了当时的本机模拟检查，但 v2.4.0 的手机外网预览未重新实测（NOT_RETESTED）。历史 v2.3.0、v2.4.0 的结果均不代替 V3 的手机验收。

Windows 10/11 x64 是发布目标，尚未在另一台没有开发环境的 Windows 电脑上验证；托盘菜单的人工点击、真实农场摄像头、检测准确率、多路长期运行和真实邮件投递仍待验证。检测可能误报或漏报，请结合实际场景确认效果。微信实测范围见仓库的 `docs/VALIDATION.md`。

## 下载校验和第三方组件

Release 同时提供 [SHA256SUMS.txt](https://github.com/zhangxutonyace-bit/MiniNVR2-Farm-NVR/releases/download/v2.4.0/SHA256SUMS.txt)，可以用 Windows PowerShell 核对下载包：

```powershell
Get-FileHash .\MiniNVR2-v2.4.0-windows-x64.zip -Algorithm SHA256
```

结果应与 Release 提供的校验值一致。包内另有文件级的 `SHA256SUMS.txt` 和不含机器路径的 `RELEASE_MANIFEST.json`。第三方许可原文保存在 `THIRD_PARTY_NOTICES`；源码来源与对应资料见 `THIRD_PARTY_SOURCES.md` 及 Release 中的第三方源码资产。此前发布版本保留。
