## 沿用的功能与历史验证

下载后配置微信，请看下方的 [微信 ClawBot 操作步骤](#微信-clawbot-操作步骤)。

**v2.4.0 新增电脑摄像头接入。** 在“摄像头”页刷新设备列表，选择电脑内置或 USB 摄像头并添加后，即可将它作为平台的一路画面来源。事件触发和停录继续使用现有检测算法，录像沿用原有回放和微信查询。预览、检测和录像共享一次设备采集，不采集麦克风。[电脑摄像头操作步骤](docs/LOCAL_CAMERA_QUICK_START.md)。

**v2.4.0 新增事件录像人物框，并修复跳框与双框问题。** “设置 → 录像”的“事件录像显示目标框”默认打开；旧配置缺少此字段时也默认打开。颜色可选红色 `#F51616`、橙色 `#E86D08`、深蓝色 `#0931C0`，只用于适应背景，均为无填充描边。设置从下一次事件开始生效，新事件的 MP4 自身包含目标框，网页回放、下载与微信取回共用同一个已完成文件；旧录像不会补框。打开时两种来源都用共享预览 JPEG 重新编码为 H.264，RTSP 分辨率可能降为通常宽 480 像素，CPU 占用增加；关闭时保留原录像方式。

以下描述旧自动 / Haar / 移动模式：事件触发规则、阈值和计时沿用原逻辑。自动与 Haar 模式的画框独立使用随程序附带的 NanoDet 人物模型和图像跟踪，静止人物也会尝试定位；移动模式仍只画移动区域。图像中的移动立即应用，只平滑小幅检测偏差和尺寸变化。短暂漏检时须有当前画面支持，且距最后一次人物确认最多保留 0.75 秒；目标离开或跟踪失败会清除。旧模式的画框无需额外下载，不识别身份、车辆或动物；V3 商城模式的目标能力见上方说明。遮挡、远处小人和快速转身仍可能漏框。模型、标注或超时失败会继续保留原画面并在摄像头状态显示警告；单帧处理预算为 0.5 秒，不积压历史帧。[验证范围](docs/VALIDATION.md)。

画框处理超时会继续保存原画面；同路旧任务未返回时，后续事件也使用原画面并提示。编码正常但收尾校验失败或超时时，保留待校验文件供人工恢复，暂不提供回放、下载或微信取回。

v2.4.0 历史验收：2026-10-19，用户在该版最终 Windows 修复程序上录制新事件，确认“框能跟随，电脑和微信播放正常”。这覆盖当次电脑、摄像头、扫码账号及测试过程，其他设备和场景仍需实际确认。[v2.4.0 更新说明](docs/RELEASE_v2.4.0.md)。

**v2.3.0 新增跨网段微信预览。** 电脑通过 NetBird 建立 HTTPS 连接，手机在移动网络或其他 Wi-Fi 中发送预览指令，点击 **“打开实时预览”** 即可在微信内查看指定摄像头。手机无需安装 NetBird 或 VPN 客户端；电脑端需安装、登录并授权 NetBird。2026-10-19，用户在最终 Windows EXE 上确认微信内可点击、合成画面持续更新；此次仅覆盖本机、该扫码账号、手机及当前移动网络，真实摄像头、其他环境和长期稳定性尚待分别验证。[远程预览配置步骤](docs/REMOTE_PREVIEW.md)。

**MiniNVR2｜让旧摄像头和闲置笔记本，重新发挥价值**

农场、养殖场和小型场地的监控需求，往往并不复杂：平时看看现场，有活动时留下录像，需要时能快速回顾。

但实际使用中，常常会遇到几个问题：

- **已有设备，仍要重复投入。** 摄像头还能用，家里也有闲置笔记本，想完善录像和管理功能，却又要考虑购买专用录像机或更换设备。
- **录像很多，查找很累。** 连续录下一整天的视频，真正想了解现场变化时，仍要反复拖动进度条。
- **长时间录像，占用存储空间。** 大量变化不大的画面持续保存，增加了存储和整理负担。
- **能看到画面，却不方便集中管理。** 多路摄像头的预览、录像和回放分散，日常查看不够顺手。
- **人在外面，查看录像不方便。** 想回顾农场情况，还得回到电脑前查找文件。

MiniNVR2 希望用更轻量的方式解决这些问题：**复用现有摄像头和闲置笔记本，搭建一套本地运行的小型智能监控平台。**

通过中文网页界面，你可以集中查看多路摄像头，在检测到活动时保存事件录像；也可以定时抽取画面，将一天的变化汇总成便于回顾的短视频，减少逐段翻找长录像的时间。

**让微信成为随身的农场录像查看入口。**

启用并完成微信 ClawBot 接入后，农场主可以把连接摄像头的笔记本留在家里，保持运行和联网。人在外面时，只需在微信中发出查看请求，可以查询指定摄像头、指定日期的事件列表，选择一段已结束的事件录像回传，也可以接收按日抽帧录像，了解农场的画面变化，无需回到电脑前翻找文件。

从复用旧摄像头、闲置笔记本，到通过熟悉的微信查看录像，MiniNVR2 让小型场地的监控更贴近日常使用习惯。

它支持历史回放、断线重连和录像保留设置，核心预览与录像在本机运行。既让旧设备继续发挥作用，也为小型场地提供一条减少新增硬件投入的监控方案。

**旧设备在家里发挥作用，农场的变化通过微信带在身边。**

网络摄像头需支持 RTSP 接入，也可使用 Windows 内置或 USB 摄像头。可接路数和运行效果取决于电脑性能、分辨率及视频编码。微信支持事件录像与抽帧录像查询；v2.4.0 曾完成一次真实摄像头事件的电脑回放与微信收件播放确认，该历史结果不代表 V3 实机验收，现场效果仍需结合实际环境验证。

项目采用 Python、Flask、OpenCV 和 FFmpeg。预览、检测与抽帧复用同一路画面。默认将共享画面与目标框编码为事件录像；关闭画框后，RTSP 事件另开录像流并在编码兼容时优先直接封装，电脑摄像头仍共享一次设备采集。实际资源占用取决于摄像头数量、分辨率和编码方式。

## 主要功能

- 多路 RTSP 摄像头管理、网页预览、启用与停用。
- Windows 内置与 USB 摄像头选择、预览、事件录像，共用原有回放和微信查询。
- 手动添加摄像头，或在用户指定的局域网范围内查找设备；扫描不会自动开始。
- 运动检测、Haar 人形检测与组合模式，按检测事件启停录像。
- 算法商城：内置 NanoDet，可下载 YOLOX Nano / YOLOX-S；14 个勾选项对应 13 个 COCO 类别，勾选目标后应用即参与事件检测。座椅暂不区分椅子和凳子，宠物只合并猫狗，桌子对应餐桌类别。
- 定时保存 JPEG 抽帧，合成为按天回顾的视频。
- 按摄像头、日期和类型查找已完成录像，支持网页播放与进度跳转。
- 新事件默认写入目标框；商城按类别使用四种固定色及中文标签，旧模式全局三色可选。模型在本机 CPU 运行，微信取回与网页回放共用同一已完成 MP4；旧录像不会补框。
- 断流重连、首帧超时处理、录像保留天数设置。
- 可选 SMTP 邮件和实验性微信 ClawBot 模块，支持事件列表、分页、单段取回和按日抽帧查询，默认均关闭。
- v2.2.3 增加微信指定摄像头的局域网预览链接：同一 Wi-Fi 点击查看单路当前画面，10分钟有效，约每秒刷新一次。[配置步骤](docs/LAN_PREVIEW.md)。
- v2.3.0 增加通过 NetBird 转发的 HTTPS 预览：手机使用移动网络或其他 Wi-Fi，在微信点击“打开实时预览”；电脑和摄像头仍留在原局域网。[配置步骤](docs/REMOTE_PREVIEW.md)。

旧模式的事件触发沿用传统视觉算法；商城模式以所选模型和目标类别触发事件，沿用连续命中、离开延时及事件上限等设置。模型均可能漏检或误报，不能将一次本机测试视为农场现场准确率保证，也不提供防入侵或事故报警保证。静止的选中物品仍可能持续触发事件，请只勾选需要的目标。

## 从源码运行

已验证环境：Windows x64、Python 3.12.10。先安装 Python 3.12 64 位，然后在本目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
```

此脚本只在项目的 `.venv` 中安装 `requirements.txt` 指定版本，不改系统 Python 包。

1. **先看演示**：双击 `Start-Demo.cmd`，打开 `http://127.0.0.1:8801`。演示会生成合成视频，数据写入独立的 `data-demo/`。
2. **正式使用**：双击 `Start-MiniNVR2.cmd`，打开 `http://127.0.0.1:8800`。首次启动摄像头列表为空。
3. 打开“摄像头”页，添加自有 RTSP 摄像头，或刷新并选择电脑内置 / USB 摄像头。设备账号密码只在本机填写，不提交到仓库。
4. 在“预览”确认画面在线，再按现场光线和距离调整“设置”中的检测参数。
5. 在“回放”查看已经完成的录像。正在写入或重封装的录像暂不列出；当日抽帧通常次日合成。
6. 从托盘“退出”或网页设置页“退出程序”关闭程序。关闭浏览器标签页不会停止录像。

默认每 720 秒保存一帧、输出 1 fps；完整运行一天约 120 帧、约 2 分钟，实际长度受运行时长与缺帧影响。抽帧会持续写盘；事件录像单独受检测状态控制。

### 其他启动方式

```powershell
.\.venv\Scripts\python.exe main.py --no-tray --no-browser
.\.venv\Scripts\python.exe main.py --data-dir D:\NVRData --port 8802
```

`--config` 可指定配置文件；`--data-dir` 或环境变量 `NVR_DATA_DIR` 指定日志与默认录像目录。若使用 `--config`，建议同时指定 `--data-dir`。端口冲突会明确失败退出。

## 本机配置与访问

常规配置、日志、录像默认分别在 `data/config.json`、`data/nvr.log`、`data/records/`。本机配置可能保存设备密码和邮箱授权码，应按个人资料保管。仓库排除了这些文件及演示数据、打包结果和测试临时目录。

默认仅监听 `127.0.0.1`。如需在可信局域网使用，先在本机“设置”中保存访问口令，再退出并使用 `--host 0.0.0.0` 重启。API、预览、截图和回放均受口令保护，浏览器登录后使用 HttpOnly、SameSite Cookie。更换口令会使旧会话后续请求失效，已有视频长连接在断开后重新鉴权。

这是本地桌面工具，附带的 HTTP 服务没有 TLS 和公网生产部署配置。不要直接做公网端口映射；远程访问需另行配置受控 VPN 或带 HTTPS 的访问层。

## 可选集成

**邮件**：在本机填写 SMTP 信息并自行测试。TLS 握手失败时程序不会继续发送登录凭据。每日邮件启用后会发送前一天的抽帧录像；请确认收件人和附件大小。

**微信**：源代码包含实验性 iLink 协议适配。默认关闭且不自动登录。只有配置记录的登录用户或 `clawbot.allowed_users` 中明确允许的用户可以请求录像；未知消息只返回帮助。

### 微信 ClawBot 操作步骤

1. **启动程序**

   完整解压下载包，双击 `MiniNVR2.exe`。电脑浏览器会打开管理页面；没有自动打开时，手动访问 `http://127.0.0.1:8800`。

2. **准备要查看的内容**

   查看事件录像时，在“回放”确认已有录制结束的片段；此功能不需要 NetBird 或远程预览。只看当前画面时，在“预览”确认摄像头在线即可，不需要先录制事件。

3. **启用微信功能**

   打开“设置”，找到“微信 ClawBot”，勾选“启用”和“已登录时自动接消息”，再点击“保存设置”。

4. **用自己的微信扫码**

   点击“扫码登录”，用手机微信扫描二维码，并在手机上确认。电脑页面显示“已登录，正在接收微信消息”后，即可使用。

5. **接收一段事件录像（可选）**

   在手机的“微信 ClawBot”聊天中，单独发送 **最新事件**。程序会回传今天最近一段已完成的事件录像，收到后点开播放。

6. **查看事件列表并选择录像（可选）**

   先发送 **今天事件**（也支持 **今日事件**），收到列表后，再单独发送 **播放第一条** 或 **播放第1条**。还可以发送 **昨天事件**、**下一页**、**上一页**。

每条消息只发送一个指令，例如先发“今天事件”，收到列表后再发“播放第一条”，不要合并成“今天事件，播放第一条”。v2.4.0 已修复中文序号播放，仍兼容“播放第1条”。列表15分钟内有效，过期或程序重启后重新查询。

使用时，电脑需保持开机、联网，程序持续运行且不进入休眠。微信登录过期后，回到电脑页面重新扫码即可。

也可用 `最新事件 农场`、`昨天事件 农场`、`事件 2026-10-18 1号` 按摄像头、日期筛选；“农场”应替换为自己的摄像头名称。列表按开始时间从新到旧，每页10条，序号固定，仅本人可用。只发送已结束且未在重封装的录像；原 `昨天 农场` 等命令继续返回抽帧录像。

V3 本机实测已确认微信“今日事件 → 播放第一条”收到列表及视频且可播放；YOLOX-S / 0.35 的杯子橙框、标签与跟随在电脑新录像上获得用户确认，未单独确认本次杯子标签在手机的可读性。v2.4.0 人物跟随和 v2.2.2 合成视频收件仍保留为历史证据。其他设备、账号、场景和长期运行未由本次测试覆盖。完整范围见 [验收记录](docs/VALIDATION.md)。

### 微信同一 Wi-Fi 查看当前画面（v2.2.3 起）

手机和电脑连接同一 Wi-Fi，在设置中启用“微信局域网预览”并保存，然后向 ClawBot 单独发送 **预览1号** 或 **预览 摄像头名称**。点击返回链接即可查看该路画面；只有一路时可直接发送 **预览**。链接10分钟有效，不提供管理权限。详细设置和打不开时的处理见 [局域网预览操作步骤](docs/LAN_PREVIEW.md)。

1. 在电脑“预览”页确认摄像头已有正常画面，在“设置 → 微信 ClawBot”启用微信并扫码登录。
2. 先取消“微信优先使用远程预览链接”，再勾选“启用局域网预览”；IPv4先留空自动选择，端口保留 `8803`，点击“保存设置”。
3. 手机连接同一Wi-Fi，向机器人单独发送 **预览1号**，点击返回链接查看画面。

页面约每秒刷新一次，无声音；到期或程序重启后重新发送指令获取新链接。电脑需持续运行。多网卡导致地址选错时，可在设置中手填电脑的Wi-Fi IPv4；更多排查方法和包内同名TXT说明见上述操作步骤。

2026-10-19 已在本机最终 Windows v2.2.3 程序完成真实微信测试：用户确认收到链接，手机点击后画面持续更新；此次未修改防火墙。其他设备及网络尚未分别验收。

### 微信在外网查看当前画面（v2.3.0 起）

只在电脑安装并登录 NetBird，控制台使用同一 NetBird 账号，允许仅包含本机的专用组使用 Peer Expose。在 MiniNVR2 保存远程预览设置，阅读转发说明后点击“同意转发并开启远程预览”。手机单独发送 **预览1号** 或 **预览 摄像头名称**，点击 **“打开实时预览”**。手机无需安装额外 VPN 应用。[完整六步配置](docs/REMOTE_PREVIEW.md)。

电脑需持续开机、联网，程序重启后要手动重新开启远程预览；单路链接10分钟有效，请勿转发。NetBird 服务商可处理经其代理转发的画面，免费档的资格和限制由服务商决定。查看事件录像继续使用原有指令，无需先配置远程预览。

V3 保留上述预览逻辑并通过本机模拟检查；本轮没有重新进行手机外网预览实测，不能用 v2.3.0 的历史结果代替 V3 重新验收。
